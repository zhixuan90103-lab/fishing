# 手机瞄准

> **单位，2026-11-24。** 这一天把鱼的重量和力调到和它的体长相称：所有的力、重量、竿和线的软硬乘 6，玩起来的节奏不变（见 [ENGINEERING.md](./ENGINEERING.md) 第 10 节同日一行）。本文里主要的表已经是新数；正文里零散的旧牛顿数（比如"出线点 4.5 牛"、"硬顶 8.5 牛"）和 11-24 以前量到的张力、重量，乘 6 才是现在的数。角度、米、秒不变。

状态：已实现。手机瞄准是物料：它把手机的姿态变成镜头的视线和竿的指向，不含抛投、抬杆和咬口。  
2026-11-24：操作分两维。镜头这一维在这里。竿的按住、松开、甩和抬杆在 [FISHING-REQUIREMENTS.md](./FISHING-REQUIREMENTS.md) 第 5 节。竿拿到瞄准以后怎么动见 [ROD.md](./ROD.md)。

手机就是鱼竿。手机指向哪，竿就指向哪。没按住时镜头跟着转过去；按住时镜头停住，手机只动竿。饵抛出去以后镜头自己转向落点、停在那里，竿仍然指着手机指的方向。

## 1. 分层

| 步 | 回答什么 | 文件 |
|---|---|---|
| 读 | 手机现在是什么姿态：三个互不串的角，展开并平滑 | `src/shore/phoneLook.js` |
| 分 | 这个姿态里多少归镜头、多少归竿 | `src/shore/aim.js` |
| 握 | 竿拿到归它的那一份，加在安装姿态上 | `src/shore/rodHold.js` 的 `setAim` |

旁边还有一个输入：

| 文件 | 回答什么 |
|---|---|
| `src/shore/finger.js` | 手指是不是按着：画面上有没有按下的指针，空格键有没有按着，按着拖了多远。它不知道按下意味着什么 |

数据只往一个方向走：手机 → 读 → 分 → 镜头和握。读不知道有镜头和竿，分不知道传感器，也不碰镜头对象和竿对象。`phoneLook.js` 和 `aim.js` 都不引 Three，可以在 Node 里跑。

`src/shore/startShore.js` 只接线：每帧在 `applyPhone` 里把 `look()` 交给 `aim.step`，按 `aim` 给的角度摆镜头，把剩下的交给 `rod.setAim`。谁算"按住"、镜头该看着什么，也由它交给 `aim.step`：手指按着是按住，玩法报出的 `fishing.watch` 是要看的点。

```
按钮「允许手机转动」
  → enable()：一次 requestPermission
  → deviceorientation（alpha、beta、gamma）
phoneLook：欧拉角 → yaw / pitch / roll → 展开 → 平滑 → look()
aim.step(look, 按住没有, dt, 要看的方向, 竿尖的方向, 线的拉力)
       → 瞄准 = 基准 + 手机转过的角度
       → 没按住：镜头追瞄准
       → 竿 = 瞄准 − 镜头
startShore：placeLook(aim.viewYaw, aim.viewPitch)，rod.setAim(aim.rodPitch, aim.rodYaw, aim.rodRoll)
rodHold 把它加在安装姿态上，FOLLOW_MAX 不管它
```

## 2. 不能破的规则

**同一个手机姿态永远是同一个瞄准。** 角度从姿态直接读，不从加速度积分，也不逐帧累加偏移。手机拿回原来的姿态，镜头和竿就回到原来的位置。朝向的读法只看当前姿态，不看走过的路，不许按"上一帧用的哪一种"来选。

**镜头和竿只有一条式子，没有模式切换。** 瞄准 = 镜头 + 竿 + 手欠着的。线上没有力时手什么都不欠，就是瞄准 = 镜头 + 竿。镜头在追什么可以换：追瞄准、不追（按住）、追一个要看的方向（饵的落点）。换的只是镜头追的目标，不改基准、不拷贝镜头，竿永远拿剩下的那一份。所以按下、松开、转向落点、看完回来都不会跳，竿在世界里的指向始终是手机指的方向。

**竿的瞄准不设上限，也不在握那一层再平滑。** 快速上抬要原样传到竿身，竿才甩得起来。噪声在 `phoneLook` 里已经去掉。`FOLLOW_MAX` 只管竿跟镜头的滞后，不管瞄准。

## 3. 读（`phoneLook.js`）

`look()` 给三个角，单位是度：

| 角 | 是什么 | 正方向 | 零点 |
|---|---|---|---|
| `yaw` | 手机背面朝哪个方向，绕竖直轴 | 向持机人的左转 | 上次回正时的姿态 |
| `pitch` | 屏幕前后倾多少 | 顶部倒向持机人，也就是把竿抬起来 | 上次回正时的姿态 |
| `roll` | 在屏幕自己的平面里歪多少 | 右缘向下 | 水平。不随回正改变 |

- **不直接用 `beta` 和 `gamma`。** 手机竖着时 `gamma` 不再表示右缘向下，并且和 `alpha` 分不开。三个欧拉角先合成机身的轴在大地坐标里的方向，三个角从这些轴上读。
- **朝向有两种读法，按倾角混合。** 从屏幕法线读：在屏幕平面里歪手机不会改变它，但手机放平时法线指着天。从右缘读：任何俯仰都能用，但歪手机会带偏它。法线接近水平时只用前者，接近放平时过渡到后者。混合的比例只由当前姿态决定。
- **展开。** `yaw` 和 `pitch` 把每个样本相对上一个样本的变化加起来，转过 ±180° 不会跳。
- **平滑。** 三个角各过一级，按目标在这一帧里匀速变化来精确积分，结果不随帧率变（`chaseAngle`）。它同时抹掉传感器噪声，和样本跟渲染帧对不齐造成的一步一步。
- **`roll` 在接近放平时渐渐不读。** 放平以后它和 `yaw` 是同一个动作。

| 常量 | 值 | 管什么 |
|---|---|---|
| `SMOOTH_RATE` | 32 /秒 | 三个角的平滑，约 30 毫秒延迟。调小更稳也更迟 |
| `FACE_FULL` | 0.6 | 法线的水平分量大于它时，朝向只从法线读。对应前后倾约 53° 以内 |
| `FACE_NONE` | 0.2 | 小于它时只从右缘读。对应前后倾约 78° 以外 |
| `ROLL_FULL` | 0.5 | 手机立起来的程度大于它时 `roll` 全量读，小于它按比例减 |

`recenter()` 把手机此刻的姿态定成 `yaw` 0、`pitch` 0。

## 4. 分（`aim.js`）

`createAim(yaw, pitch)` 记着一个方向和它的两份：

| 量 | 是什么 |
|---|---|
| 瞄准 | 基准 + 手机转过的角度 × 增益。基准是手机在零点时视线的朝向 |
| `viewYaw`、`viewPitch` | 镜头现在朝哪 |
| `rodYaw`、`rodPitch`、`rodRoll` | 瞄准 − 镜头，在镜头空间里：左转、上抬、绕视线的歪斜。`rodRoll` 是手机的 `roll` 取反，右缘向下时竿尖向屏幕右 |

单位都是度。偏航向镜头的左为正，俯仰向上为正。`roll` 只进竿，不进镜头。

### 镜头在追什么

`step(turned, held, dt, watch, tip, pull)` 每帧一次。镜头永远在追三样里的一样，竿永远拿瞄准减镜头：

| 镜头追 | 什么时候 | 怎么追 |
|---|---|---|
| 瞄准 | 平时 | 按 `LOOK_RATE`。刚看完别的东西交还回来时慢一些，见下 |
| 什么都不追 | `held`：手指按着 | 镜头不动，手机只动竿 |
| 一个方向 | 给了 `watch`：玩法指了一个要看的点。它压过 `held` | 按 `WATCH_RATE` 转过去。俯仰留在 `WATCH_PITCH_MIN` 到 `WATCH_PITCH_MAX` 之间，偏航走近的那一边 |

三样之间换，只是换镜头追的目标。代码里是两个函数：`turnTo` 追一个方向，`followAim` 追瞄准。

**要看的方向不动，镜头就只转一次。** 镜头朝它逼近，越近越慢，不会过头，也不会来回。玩法给的是落点这样的定点，所以甩出去以后画面是一次平顺的转动，没有上下起伏。给它一个一直在动的点它也会跟，但那样画面就跟着晃，不要这样用。

**看完交还给手机时不甩头。** 这时手机指的方向可能离镜头看的地方有几十度。按平时的 `LOOK_RATE` 去追，镜头会在十分之一秒里甩过去，看起来像跳了一下。所以交还以后追的速度从 `RETURN_RATE` 起步，再按 `RETURN_RECOVER` 回到 `LOOK_RATE`。相差 45° 时最快约 80°/秒，一秒后剩 1°。

**看着一个方向时可以把竿尖留在画面里。** 给了 `tip`（从眼睛到竿尖的方向），竿尖就有一个窗口：画面里它可以待的一块地方。

- 竿尖在窗口中间时，镜头不理它，只管转向要看的东西。竿尖怎么点头、怎么颤都不影响镜头。
- 竿尖靠近窗口的边，镜头被它推着走，推到刚好把它留在窗口里。是越靠边推得越多（`tanh`），不是撞上去。
- 所以竿不会丢。要看的东西可能偏到画面边上甚至出去，拿手机的人靠带竿把它领回来，或者转过去追它。
- 交进来的竿尖先按 `TIP_STEADY` 缓一下。竿尖正好贴在窗口边上抖的时候，镜头不能被它一下一下地顶。`startShore` 给的本来就是不带弯、不带点头的竿尖（`rod.steadyTip`），这里再去掉手的颤。
- 竿尖可以把镜头推过 `WATCH_PITCH_MAX`：手机举高了，先保竿，再保水面。
窗口左右不一样宽。竿握在右手，从画面右下角伸出来：竿尖偏左时竿斜着横过整个画面，偏右时竿身大半已经从右边缘出去了。

原来试过两种别的：让镜头离瞄准不超过一个角度，左右各 8°，往右带竿时竿从右边缘出去；再改成左 8° 右 2°，竿弯了、抬高了以后这个角度又不准。直接看竿尖在画面里的位置就没有这些问题。也试过让镜头直接跟竿尖的位置：竿尖在抖，镜头跟着晃。

现在从钩住到抄网把鱼带走都给 `tip`，遛鱼和提鱼都是；甩出去以后看落点时不给，因为那时手机可能举在任何地方，镜头要去看水。没有传感器时也不给：桌面上竿转不了，镜头只能自己跟。

量过（竿尖用手机的方向加 18° 代替，手机 0.4 秒里猛拽 35°）：竿尖落定在中线左 11.5° 或右 6.5°，途中在画面外 0.4 到 0.7 秒（这组数是窗口为左 11.5°、右 6.5°、上 24.5° 时的；窗口最初是左 9.5°、右 4°、上 22°，真机上觉得留的边太多）；鱼偏 30° 时竿尖稳在窗口边上，镜头不动；手机抬高 30°，竿尖出画面 0.6 秒后被追回来。20、60、120 帧一样。

**镜头从谁手里交出来，都是缓缓起步的。** 镜头不在追瞄准的时候（被按住，或者在看一个方向），手机可能已经转到了别处。交还的那一刻如果直接按 `LOOK_RATE` 去追，就是一下甩过去：量到过按住时手机下摆 50°、松手那一帧镜头从不动跳到每秒 488°。所以这两种情况都把追的速率放回 `RETURN_RATE`，再按 `RETURN_RECOVER` 加回来。竿尖的窗口也一样：鱼咬钩那一刻竿尖才开始算数，它可能离窗口很远，窗口和加速在 `KEEP_EASES_IN` 里加上来。量过五种交接（按住后松手、提鱼后松手、遛完鱼、甩出去看落点、鱼咬钩），镜头的转速一帧里最多变每秒 15°。

### 逆着线的力，手跟不上手机（`handLag.js`）

手机指的方向是手想把竿带去的地方。线在拉的时候手跟不上：

| 情况 | 竿和手机 |
|---|---|
| 线上没有力 | 1 比 1 |
| 顺着线的拉力让过去 | 1 比 1，不多欠 |
| 逆着线的拉力带竿 | 小于 1。只算这一下转动里"让竿离拉力更远"的那一份，力越大欠得越多 |
| 手停着，力还在 | 欠着的慢慢补上，力越大补得越慢 |
| 力掉下去 | 欠着的按同样的比例跟着退：力掉多快，补得多快 |

- 竿从来不超过手机指的方向。手不转的时候什么都不欠，所以鱼在旁边怎么窜，竿和镜头都不会被它带走。
- 没有"回正要几秒"。力一下子没了（鱼掉头朝你游、线断），竿在五分之一秒里扫到手机指的地方，那是手读到力没了要的时间（`FEELS`）。
- 它是按转过的角度算的，不是按时间，所以各帧率一样。
- **镜头欠得比竿少**（`VIEW_OWES`）。镜头留竿尖用的那个方向，按竿欠的一部分往手机那边挪回去。手转 1、竿走 0.6 时镜头走约 0.8，竿在画面里就往鱼那边落后一截，看得出它在受力。两个欠得一样多的话竿在画面里不动。
- 同一个手机姿态仍然是同一个瞄准。欠着的是握竿的手的状态，有上限，力没了就清掉，不会越用越偏。

力和它从哪来由 `startShore` 交进来：线的张力，和从眼睛到线的远端的方向。它不知道那一头是什么。

量过（2026-11-19，手机半秒里转开 30°）：没有力 30°；1 牛约 27°；2.5 牛约 22°；4.5 牛（出线点）约 19°，也就是六成多；8.5 牛（硬顶）约 15.5°。20、60、120 帧相差不到 0.6°。停住三秒以后：4.5 牛补到约 27°，8.5 牛约 22°，都不超过 30°。力一下子没了，0.2 秒到 28.5° 以上；力在一秒里慢慢退，同样的 0.2 秒只多走几度。

| 常量（`handLag.js`） | 值 | 管什么 |
|---|---|---|
| `FULL_AT` | 54 牛 | 手用尽全力的力。和 `src/play/strain.js` 的是同一个数 |
| `HEAVY` | 2.2 | 那个力比手强几倍。力到 `FULL_AT` 时逆着转只走 1/(1+它)，一半力（出线点）时约六成。调大，鱼把竿顶得更死 |
| `MAKES_UP` | 0.45 /秒 | 力和手打平时，欠着的多快补上。力更大就按比例更慢 |
| `OWES_MOST` | 30° | 最多欠多少。越接近越不再多欠 |
| `FEELS` | 14 /秒 | 手读到的力跟线上的力跟得多快。竿在咬钩那一下回弹，张力会掉一两帧，手不因此松掉 |
| `ALONG` | 2° | 竿几乎顺着拉力指时，没有"更远离拉力"这个方向可言 |

| 常量（`aim.js`） | 值 | 管什么 |
|---|---|---|
| `VIEW_OWES` | 0.5 | 竿欠的里面镜头分担几成。1 是镜头和竿欠得一样多，竿在画面里不动；0 是镜头完全不欠 |

只做了镜头留竿尖的那条路：竿尖还在窗口中间时镜头本来就不跟，所以"镜头 0.8"只在竿尖顶着窗口边时成立。

`reset(yaw, pitch)` 把基准和镜头都定到这个方向，竿的那一份清零。`directionTo(eye, point, out)` 把"从眼睛到一个点"换成 `watch` 要的偏航和俯仰。

| 常量 | 值 | 管什么 |
|---|---|---|
| `AIM_YAW_GAIN` | 1 | 手机左右转 1°，瞄准转多少度。镜头和竿共用，调大两者都更灵敏 |
| `AIM_PITCH_GAIN` | 1 | 手机前后倾 1°，瞄准抬多少度 |
| `LOOK_RATE` | 10 /秒 | 镜头追瞄准的快慢。匀速转动时镜头落后转速除以它，60°/秒时约 6°，竿在画面里领先同样多 |
| `PITCH_LIMIT`、`PITCH_EASES` | 70°、55° | 镜头的俯仰留在 70° 以内。不是撞上去的：55° 以内原样，再往外越来越慢地靠近 70°，永远到不了。原来是硬夹，手机抬过头镜头一下子顶死。镜头没拿走的那一份照旧给竿，竿不受它限制。桌面拖动和面板滑条仍是到 70° 为止 |
| `WATCH_RATE` | 3 /秒 | 镜头转向要看的方向的快慢，大约三分之一秒走完一多半，一秒走完九成五。调小转得更慢更稳 |
| `WATCH_PITCH_MAX` | 6° | 看着一个方向时最多仰这么高。水面留在画面里 |
| `WATCH_PITCH_MIN` | −40° | 看着一个方向时最多低这么多。要看的点很近时不一路低头看到脚下 |
| `TIP_LEFT`、`TIP_RIGHT` | 11.5°、6.5° | 竿尖的窗口：它最多在画面中线左边、右边多少度。画面左右各到约 13.5°。调大镜头少动，竿尖更靠边 |
| `TIP_UP`、`TIP_DOWN` | 24.5°、0° | 同上，中线上面、下面。画面上下各到约 27.5° |
| `TIP_STEADY` | 12 /秒 | 竿尖的方向先缓多快再给窗口用。调小更稳，猛拽时镜头跟得更迟 |
| `KEEP_RATE`、`KEEP_HURRY_BY` | 8 /秒、10° | 有 `tip` 时，镜头离该在的地方越远追得越快，差到后一个数时用前一个速率 |
| `KEEP_EASES_IN` | 0.8 秒 | 从竿尖开始算数起，窗口和上面的加速用多久加上来 |
| `RETURN_RATE` | 0.2 /秒 | 看完以后镜头交还给手机时，一开始追瞄准的快慢。几乎是不动 |
| `RETURN_RECOVER` | 1 /秒 | 之后多快回到 `LOOK_RATE`。镜头先缓缓起步、转过去、再停稳，全程约一秒。调小更慢更柔 |

没有死区。这些常量在 `aim.js` 顶部。

### 接线（`startShore.js` 的 `applyPhone`）

在 `rod.update` 之前，每帧：

1. 第一帧样本：回正一次，去掉按钮。
2. 有样本：`phone.advance(dt)` 平滑，读 `look()`。没有样本：当作手机没转过，瞄准停在设置面板的朝向上。
3. 玩法有要看的点：`directionTo` 算出从眼睛到它的方向。
4. `aim.step(look, 按住没有, dt, watch, tip, pull)`。按住是"有手机，并且手指按在画面上"，手指从 `finger.js` 读。`watch` 是上一步的方向，没有就是 `null`。`tip` 是竿尖在哪个方向（`rod.steadyTip` 换成的方向），只在 `fishing.watchRod` 为真并且有传感器时给。`pull` 是线拉竿尖的力和方向，线没有拉时是 `null`，手欠多少由它算。
5. `placeLook` 摆镜头。眼在设置面板给的位置，`camera.up` 是世界 +Y，地平线不跟着滚。
6. `rod.setAim`。

**回正。** `aim.reset` 和 `phone.recenter` 一起调用：把手机此刻的姿态当成设置面板里的摄像机朝向。三处会调用：第一帧样本，设置面板的「镜头回正」，改「摄像机」的任一滑条。iOS 的朝向没有罗盘参照，时间长了会慢慢偏；人换了站姿也要用它。

**没有传感器时**（桌面，或没给权限）拖动画面改朝向，写回设置滑条，和手机走同一个 `placeLook`。瞄准停在拖到的朝向上，竿不受控制。镜头看着落点的那段时间拖动不起作用。拖动由 `finger.js` 报出，每拖一个像素转 `DRAG_DEG_PER_PIXEL`（0.17°，在 `startShore.js` 顶部）。

## 5. 给玩法留的口子

玩法不直接动镜头，只报出它想让镜头看着的点：

| 接口 | 作用 |
|---|---|
| `fishing.watchRod` | 真或假。看着 `watch` 的时候要不要把竿留在画面里。现在从钩住到网把鱼带走都为真。为真并且有传感器时，`startShore` 把 `rod.steadyTip` 换成方向交给 `aim.step` 的 `tip` |
| `fishing.watch` | 一个世界坐标的点，或者 `null`。有点时镜头转过去看着它，竿继续跟手机；`null` 时镜头是手机的。从饵离开竿尖到它被提出水面，是饵的落点；挂着鱼时这个点慢慢跟着鱼，鱼被提出水面以后跟着钩上的饵，连高度一起。见 [PLAY.md](./PLAY.md) 第 3、8 节 |

`startShore` 每帧读它，用 `directionTo` 算出从眼睛到这个点的方向交给 `aim.step`。玩法的 `update` 要在 `applyPhone` 之前，这样饵离开竿尖的那一帧镜头就开始转向落点，不会先朝手机指的方向追出去一截。

要看别的东西也是改 `watch` 报出的点，不在这一层加模式。报的点尽量是定点，或者只在事情变了的时候换一次；非跟着动的东西不可时（挂着的鱼），让这个点慢慢地追，不要直接给鱼的位置。

玩法要读"手机抬得多快"时（抬杆，还没做），读瞄准的俯仰（`aim.viewPitch + aim.rodPitch`），由 `startShore` 每帧传给它，快慢由玩法自己量，不要在这一层写规则。抛投的力度不读手机：读竿尖的速度，饵是从竿尖离手的，见 [PLAY.md](./PLAY.md) 第 4 节。抛投的方向是手指按下那一刻镜头的朝向和俯仰（`viewYaw`、`viewPitch`，同样每帧传给玩法）。

权限只由「允许手机转动」的点击去要：`enable()` 在那一次点击里同步调用，一次只请求一个接口。iOS 上 Capacitor 的 WebView 会静默放行而不弹框，所以 `BridgeViewController.swift` 里的 `MotionPromptProxy` 必须 `decisionHandler(.prompt)`。它的真源在 `plugins/native-haptics/`。

## 6. 还没做

- 算式是在合成的姿态数据上验的。手机上方向和手感哪些已经认可，这里没有逐条记。
- 抛投的力度由玩法量：读的是竿尖的速度，不读瞄准的俯仰（第 5 节，[PLAY.md](./PLAY.md) 第 4 节）。抬杆的判定还没做。
- 给玩法读手机转动快慢的口子。
- 手机的平移不读。左右看靠转动手机。
- 桌面上竿不受控制。
- 看着落点时只转镜头，不改视野和眼睛的位置。饵在远处仍然只有几个像素。

## 7. 改的时候

- 哪个方向反了：改 `phoneLook.js` 的 `onDevice` 里那一个角的符号。别处不改。
- 想改灵敏度、镜头跟得多紧、转向要看的点时多快和上下限、交还时多柔：改 `aim.js` 顶部的常量。
- 想让镜头在某个时候看别的地方：改玩法报出的 `watch`，不在 `aim.js` 里加第四种情况。
- 想改什么算手指按着、桌面用什么代替：改 `finger.js`，以及 `startShore.js` 里取哪一个的那两处。
- 想改镜头和竿怎么分：只改 `aim.js`，并且守住"瞄准 = 镜头 + 竿"。不要把这段算式写回 `startShore.js`。
- 想改什么时候算按住：改 `startShore.js` 的 `applyPhone` 交给 `aim.step` 的那个布尔值。
- 想改稳不稳：改 `SMOOTH_RATE`。不要在 `rodHold` 里给瞄准再加一级平滑。
- 只用 Web 的 `deviceorientation`。不加 Core Motion，不把 `@capacitor/motion` 当成另一套传感器，不从 `devicemotion` 的加速度积分位移。
- 改了常量，同一次改动里把第 3、4 节的表改掉。
- 改完在 Node 里验，见 [CONVENTIONS.md](./CONVENTIONS.md) 第 7 节：`phoneLook.js` 喂合成的姿态，`aim.js` 喂一段固定的转动和按住松开。方向和手感只能真机看。
