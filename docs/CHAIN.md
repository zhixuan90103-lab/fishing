# 因果链

状态：设计，分段在做。2026-11-19 讨论定下的方向，第 1 段（手这一头）同一天做完，其余四段还没动。现在的代码哪些已经是这样、哪些还不是，见第 5 节；分几段改、每段怎么验，见第 6 节；讨论定下来的做法在第 7 节。  
这份文档管的是"力和运动从哪来、经过谁、到哪去"。每样东西自己怎么做，仍在各自的文档：[ROD.md](./ROD.md)、[LINE.md](./LINE.md)、[LURE.md](./LURE.md)、[PLAY.md](./PLAY.md)。

## 1. 一句话

只做好几样东西各自的物理，和它们之间怎么传。玩家和鱼各在一头往这条链上加东西，甩竿、遛鱼、拔河都是结果，不另写规则。

```
手（手机）──握把的运动──▶ 竿 ──竿尖的运动──▶ 线 ──线的拉力──▶ 线头上的东西
    ◀──握把上的力────── 竿 ◀──线的拉力──── 线 ◀──它自己的力和运动── （饵，或者咬着饵的鱼）
                               ▲
                              渔轮：线放出多长
```

- 往右传的是**运动**：手把握把带到哪，竿尖因此到哪，线头因此被带着走。
- 往左传的是**力**：线头上的东西拉线，线拉竿尖，竿把力传到握把上。
- 线上只有**一个张力**。它在线的两头是同一个数，鱼、竿、手感到的是同一股力。

## 2. 五样东西

每样东西有自己的参数，不知道别的东西是什么，只认识它两边的接点。

| 东西 | 它自己的物理 | 参数 | 现在在哪 |
|---|---|---|---|
| 手 | 手机给握把的位置和朝向。玩家松不开竿，所以它是这条链的锚；但它的力气有限度，逆着线的力带竿时跟得慢 | 手有多大力气算"用尽全力"；逆着多大的力只跟得上几成；镜头分担几成（第 7 节） | `rodHold.js`、`rodHand.js`、`phoneLook.js`、`aim.js` |
| 竿 | 一根沿长度软硬不同的梁，有惯性，会弯。握把一动它落在后面再弹过去；竿尖受力它就弯 | 长度、软硬表、质量表、阻尼 | `rodBeam.js`、`rodFlex.js` |
| 渔轮 | 决定线放出多长。三种状态：线挡开着（线随便出）、收线（按摇把的快慢收，线越紧越收不动）、泄力（张力过了出线点就让线） | 出线点、收线的快慢、线杯上有多少线 | 散在 `retrieve.js`、`haul.js`、`lineOut.js`、`looseLine.js` |
| 线 | 有长度和弹性。两头的距离比线长长，就按拉长多少出力；短，就没有力。它怎么松、怎么被拉直是它自己的样子 | 软硬、下沉多快、被拉直时拖住它的阻力 | `line.js`、`lineCurve.js` |
| 线头上的东西 | 一个有重量的东西，在空气或水里。饵：重量、水的阻力、下沉。鱼：它自己的力（冲和歇）、它在水里被拖动的阻力、出水以后的重量 | 饵多重、沉多快；每条鱼的表（`fishKind.js`） | `lureMove.js`、`fight.js`、`flock.js`、`tipWeight.js` |

## 3. 接点：谁把什么交给谁

| 接点 | 往右（运动） | 往左（力） |
|---|---|---|
| 手 ↔ 竿 | 握把在哪、朝哪 | 握把上的力：线的张力，以及它在竿上的力臂 |
| 竿 ↔ 线 | 竿尖在哪 | 张力，沿着线指向线头 |
| 渔轮 ↔ 线 | 线现在放出多长 | 张力（渔轮据此收得动、收不动、让线） |
| 线 ↔ 线头 | 张力，沿着线指向竿尖 | 线头在哪 |

张力只有一个算法：线被拉长多少 × 线的软硬。它不是填进去的数。

## 4. 不能破的规则

**只有两头能往链上加东西。** 一头是手机（握把的运动、手指按没按着），一头是线头上那样东西自己的力（饵的重量，鱼的力）。中间的竿、轮、线只传，不凭空加力，也不凭空加运动。想让竿更弯，只能是手把握把带远了，或者线头拉得更狠了。

**中间的东西不知道两头是谁。** 竿不知道拉它的是饵还是鱼。线不知道远端是什么。有没有鱼是同一套。

**状态不被告知，也不按时间走。** 线松不松、线拉不拉竿、竿上有多重，都是算出来的结果。不许有"玩法说现在松着""玩法说现在线不拉竿"这样的开关，也不许有"几秒以后自己变直"。

**手上的力就是握把上的力。** 手多吃力从竿上读，不另算一份。

**鱼是活的，不被线拖着走。** 鱼挂上链以后受张力影响，但张力是变成它的游动目标（朝向、速度），由它自己游过去，不直接挪它的位置。这条和 [FISH-SCHOOL.md](./FISH-SCHOOL.md) 第 2 节一致。出了水的鱼是挂在线头的重物，那时它才真的被线带着。

**互相拉着的东西在同一个细步长里算。** 竿尖、线、线头上有重量的东西是硬连在一起的。隔着一帧互相读，张力就在零和尖峰之间跳（试过：让线带着鱼的重量去拉竿，见 [PLAY.md](./PLAY.md) 第 10 节）。所以它们要进同一个 1/480 秒的小步。水里游着的鱼例外：它一帧只动一次，对竿和线来说是这一帧里匀速挪动的一个点。

**仍然是规则、不进这条链的。** 鱼自己的行为（什么时候冲、歇多久、往哪边冲、咬不咬），抄网，震动怎么对应，镜头看哪，一竿走到哪一段。这些是"两头往链上加什么"和"画面怎么呈现"，不是传递。

## 5. 现在和它差在哪

已经是这样的：

- 鱼 → 线 → 竿：张力由线长和两端算，竿在自己的细步长里被它拉弯，两边自己平衡。
- 反着带竿：竿尖离鱼远了，线拉长，张力升高，竿更弯，过了出线点线就出去。
- 线的松紧：只由发生过的事和线上的力决定（[LINE.md](./LINE.md) 第 3 节）。
- 手的吃力：直接读线拉竿的力。握竿的手逆着线的力带竿时欠着，力没了补上，手不转就不被带走；镜头欠得比竿少。

还不是这样的：

| 环节 | 现在 | 按因果链 | 涉及的文件 |
|---|---|---|---|
| 领鱼 | 按竿指的方向和鱼的夹角直接给一个横向速度 | 张力作用在鱼嘴上，把鱼头往竿尖那边带；鱼越使劲越带不动 | `lead.js`、`fight.js`、`catch.js` |
| 鱼的气力 | 冲的时候按时间掉，被收回来时按米掉 | 它扛着多大的张力，就耗多快。往回拽、硬顶都让它耗得更快 | `fight.js` |
| 抬竿 | 只改竿弯多少 | 不用另做：竿尖抬高，线拉得更长，张力就不一样，自然传到鱼身上 | — |
| 饵的重量 | 不压竿 | 饵是线头上有重量的东西，经过线压在竿尖上 | `lureMove.js`、`rodFlex.js` |
| 出水的鱼的重量 | 单独一个口子 `rod.setTipLoad` 交给竿 | 同上，经过线 | `tipWeight.js`、`catch.js`、`rod.js` |
| 线拉不拉竿 | 玩法用 `line.setTied` 开关 | 线有力就拉，没有就不拉。饵在飞时线是松的，自然不拉 | `line.js`、`fishing.js`、`catch.js` |
| 饵怎么动 | 四种动法（固定、挂、飞、拖）由玩法每帧选一种 | 一个有重量的点：重力、空气或水的阻力、线的拉力。挂、飞、沉、被拖都是它在不同情况下的样子 | `lureMove.js`、`fishing.js` |
| 线放出多长 | 四个文件各管一段，飞行时"距离多千分之一"、落水后余线自己退 | 渔轮一样东西：线挡开着就随线头带，按住就收，过了出线点就让 | `retrieve.js`、`haul.js`、`lineOut.js`、`looseLine.js` |
| 抛投 | 读手机的角速度，查表得出抛多远，饵按算好的弧线飞 | 竿尖带着饵走，松手那一刻饵有多快、朝哪，就飞多远 | `swing.js`、`fishing.js`、`lureMove.js` |

## 6. 分几段改

从链的两头往中间做，每一段做完都能单独跑、单独验，并且游戏一直是能玩的。每段开始前先把上一段提交掉；每段都要过 `npm run check`，新的行为在 `checks/check.mjs` 里加项，量出来的数写回对应的设计文档。

### 第 1 段：手这一头（做完了）

2026-11-19 做完，只在 Node 里验过，真机没有试。手的吃力直接读线的张力；握竿的手换成 `handLag.js`；镜头欠得比竿少。量到的数在 [PHONE-LOOK.md](./PHONE-LOOK.md) 第 4 节和 [PLAY.md](./PLAY.md) 第 9 节。下面是当时的计划。

- 手的吃力从竿上读：握把上的力就是线的张力和它的力臂。`strain.js` 只剩"把力变成 0 到 1、缓一下"这一件事，`handHolds` 那套上游的估算删掉。
- 握竿的手换成第 7 节定的那样：逆着力带竿时欠着，力掉了补上，镜头欠得比竿少。
- 验：手的吃力和线的张力在冲、歇、收线、硬顶时逐帧对得上；20 帧和 60 帧一样；握竿的手自己的颤不会把张力带着一起抖起来。
- 风险：以前不从张力读，是因为手一让、竿尖一动、张力跟着变，隔着一帧互相追。现在手欠多少也要看张力，这个回路还在：读的力要先按"力沿着线传过去要多久"缓过，欠的量有上限，并且在 20、60 帧下量张力有没有被带着抖起来。

### 第 2 段：鱼这一头

- 张力进到鱼身上。领鱼改成"张力把鱼头往竿尖那边带"，带得动多少看张力和鱼自己的力谁大。用的是竿尖真的在哪，不是手机指的方向。
- 气力改成按它扛的张力耗。
- `lead.js` 的规则和 `against` 删掉。需求文档里气力和领鱼的两段要跟着改，注明日期。
- 验：歇着的鱼带得过来、气力满的冲着的鱼带不动，这两条现在的检查要原样通过；往回拽、硬顶时鱼确实累得更快，量出来快多少；每档鱼遛多久重新量，和现在的数对比。
- 风险：遛鱼的时长会变。大鱼现在只在歇的时候按要 49 到 70 秒，改完以后会拽的人会更快。

### 第 3 段：线头是一个有重量的东西

- 饵变成一个有质量的点，挂、沉、被拖合成一种算法。竿尖、线、饵进同一个细步长。
- 饵和出水的鱼的重量经过线到竿尖。`rod.setTipLoad` 这个口子、`tipWeight.js`、`line.setTied` 开关删掉。
- 验：空杆时饵在竿尖下面把竿压出一点弯；提鱼时竿被压低多少，20 帧和 60 帧一样，和现在量到的数对比；竿尖在到身边、脱钩、落网那几下没有一帧的弹跳。
- 风险：这是技术上最难的一段。短而硬的线挂着重物，正是以前跳过的地方。先在 Node 里单独把"竿尖 + 一段线 + 一个重物"跑稳，再接进来。

### 第 4 段：渔轮

- 线放出多长收成一样东西，三种状态：线挡开着、收线、泄力。`retrieve.js`、`haul.js`、`lineOut.js`、`looseLine.js` 里和线长有关的部分并进来。
- 空竿收线"先慢再匀速"是需求里定的，保留，它是手摇得多快，不是线的事。
- 验：各帧率下收的线长一个数都不差；出线时张力停在出线点上；松着手饵竖直下沉、抖竿只把饵带回来一点，这两条现在的检查原样通过。
- 这一段主要是整理，行为应当基本不变，用 `npm run record` 对比，变了的地方逐条说明。

### 第 5 段：抛投

- 饵挂在竿尖下面，手指按着就是压着线。甩的时候竿尖带着饵走，松手线放开，饵带着当时的速度飞出去。飞多远由速度、空气和线的拖累决定。
- `swing.js` 的查表删掉。
- 验：同样的一甩在各帧率下落点一样；轻甩近、重甩远，中间分得开；普通一甩（400°/秒）落在 15 到 20 米。
- 风险最大，放最后。以前试过从竿尖读速度：手以 220°/秒甩，竿尖只有约 1.2 米/秒，而且最快的时候手已经停了。这一段先做的事是把这个数查清楚（竿太软、饵没压在竿上、还是握把那层的平滑），再决定怎么接。出手的仰角和方向固定，见第 7 节。

## 7. 定下来的

2026-11-19 讨论定的。第 6 节各段照这里做。

### 手：有限度，逆着力带竿是沉的

手机指的方向（瞄准）不变，同一个姿态还是同一个瞄准。变的是握竿的手跟不跟得上：

| 情况 | 竿和手机 |
|---|---|
| 线上没有力 | 1 比 1 |
| 顺着线的拉力让过去 | 1 比 1 |
| 逆着线的拉力带竿 | 小于 1，力越大越小。手动了 1，竿只走一部分，剩下的欠着 |
| 手停着，力还在 | 欠着的慢慢补上，力越大补得越慢 |
| 力掉下去 | 欠着的跟着力一起退：力掉多快，补得多快。力一下子没了，就一下子补上 |

- **看的是线上此刻的力和方向，不是鱼的大小或它在不在冲。** 同一条鱼，顶着你时沉，顺着你游时是轻的。
- **竿不会超过手机指的方向，最多追平。** 顺着让、没有力、力没了，都是回到 1 比 1，没有比 1 更快的。
- **手不动时竿不被鱼拖着走。** 2026-11-19 上午做的那一版是把竿拉向鱼所在的方向，鱼往旁边一窜，竿和镜头跟着被带过去，目标就丢了。那一版换掉。
- **补上没有固定的时间。** 欠着的量跟着力走：力慢慢松，竿慢慢到位；鱼突然掉头、脱钩、线断，竿一下子扫过去。线上没有力时，竿跟手机和空竿时一样快，那是竿自己的快慢，不另外加一个回正的时间。
- **"变快感"是三样东西一起回到正常**：比例回到 1，欠着的补上，竿里存的弯弹直。

硬性约定第 14 条"不逐帧累加偏移"说的是瞄准，仍然成立。竿欠着的这一段是握竿的手的状态，有上限，力没了就清掉，不会越用越偏。改的时候把第 14 条的措辞补上这一句。

### 镜头：欠得比竿少

角力时手动 1，镜头走得比竿多：比如镜头 0.8、竿 0.6。两个数都跟着力变，没有力时都是 1。

- 镜头和竿欠得不一样多，竿在画面里才会往鱼那边落后一截，看得出竿在受力。两个一样多的话，竿在画面里的位置不变，力就看不出来。
- 镜头欠的是竿欠的一部分，只多一个参数：镜头分担几成。
- 力没了镜头也补上，但照镜头现在的方式缓着到位，不跟着竿一起甩：竿窜出去是对的，镜头猛甩会丢目标。
- 同时竿抖得多一点、弯得多一点，幅度都跟着力走。

### 抛投

快慢照实：竿尖带着饵走，松手时饵有多快就飞多快。仰角和左右方向仍然固定。真机上试过以后再看要不要放开。

### 拔河：力的差决定谁被带动，自己使的力决定谁累

| | 取决于什么 |
|---|---|
| 鱼被带动多少、往哪边 | 线的拉力和它自己的力，谁大、大多少。它不使劲，1 的力带动它 1；它也使劲，要带动它 1 就得用更多的力 |
| 鱼累得多快 | 它自己使了多大的力、使了多久。不是它受了多大的力 |

- 一条放松的鱼被拖回来，没怎么使劲，也就不怎么累。顶着线冲的鱼，使多大劲耗多快。往回拽不直接让它更累，是逼它要么使更大的劲顶住，要么被带过来。
- 现在"被带动多少"基本已经是这样；"累得多快"现在只看它在不在冲、冲了多久，要改成按它实际使的力算。需求文档里气力那一段跟着改，注明日期。

### 鱼被带着掉头是划弧线

鱼只能往前游。它松下来被带向反方向时，是线的拉力作用在鱼嘴上，把鱼头往竿尖那边带，身体跟着划一个弧转过来，像汽车掉头。带得多快看拉力和它自己的力谁大；它一边转一边继续往前游，转弯的半径跟着它的速度走。

现在的做法是"要转的角度超过直角时把速度降到两成再转"，像停下来挪过去。第 2 段换掉。

鱼掉过头顺着玩家带的方向游，线上的力才会真的掉下去，上面"变快感"才完整。所以第 1 段做完先有"逆着带很沉"，变快的那一下要等第 2 段。
