# 规范

做这个工程时要守的约定，按主题排。不能破的壳约定在 [AGENTS.md](../AGENTS.md) 的"硬性约定"，这里不重复，只写做内容时的规矩。

每一条后面的文档是它的出处，细节以出处为准。

## 1. 物料和玩法分开

工程里的代码分四种，各有各的地方：

| 种类 | 是什么 | 在哪 |
|---|---|---|
| 物料 | 自己能看、能动，不含钓鱼规则：水面、鱼群、鱼竿、渔轮、鱼线、饵、水花、抄网、手机瞄准 | `src/shore/`、`src/fish/` |
| 玩法 | 钓鱼的规则。只算数的各回答一个问题；接线的两个（`fishing.js`、`catch.js`）通过物料留的口子驱动它们 | `src/play/`，见 [PLAY.md](./PLAY.md) |
| 输入和界面 | 手指按没按着，设置面板。不知道按下意味着什么、滑条管什么 | `src/shore/finger.js`、`src/shore/tunePanel.js` |
| 接线 | 创建上面这些，决定谁的数交给谁，定每帧的顺序 | `src/shore/startShore.js` |

- 钓鱼的规则只写在 [FISHING-REQUIREMENTS.md](./FISHING-REQUIREMENTS.md)，代码只写在 `src/play/`。不要在水面、鱼群、鱼竿、鱼线、饵、抄网里另写一套抛投、咬口或拔河。
- **什么时候、多用力归玩法，成什么样归物料。** 鱼什么时候猛甩、甩几成力是玩法定的（`kick.js`），甩成什么样是鱼的事（`hung.js`）。网什么时候来、走哪条路是玩法定的（`scoop.js`），网长什么样、网兜怎么拉长是网的事（`net.js`）。物料收一个数，不问为什么。
- 物料对外只给**口子**，不给内部状态。现有的口子：

| 物料 | 玩法往里送什么 | 玩法从里读什么 | 出处 |
|---|---|---|---|
| 鱼群 | `take(fish, brain)`、`giveBack(fish)`；`brain` 里只写目标。出了水的鱼用 `hang`、`keep` | `fishes`、`mouth(fish, out)` | [FISH-SCHOOL.md](./FISH-SCHOOL.md) 第 6、7 节 |
| 鱼竿 | `setPose(pose)`；`setTipLoad(kg)`：出了水、挂在线上的重量 | — | [ROD.md](./ROD.md) 第 6 节 |
| 渔轮 | `rod.reel.wind(米)`，或单独转 `rotor` / `handle`、移 `spool` | — | [ROD.md](./ROD.md) 第 7 节 |
| 鱼线 | `setEnd`、`setLength` / `tighten`、`stow`、`setTied` | `slack`、`tension`、`stiffness`、`tip`、`end` | [LINE.md](./LINE.md) 第 4 节 |
| 饵 | `lureMove` 的 `hold` / `hang` / `launch` / `fly` / `tow` / `point`，在鱼嘴里时 `place`；`lure.place` | 位置、速度、鼻尖朝向、`swum`、`impact` | [LURE.md](./LURE.md) 第 5 节 |
| 水花 | `burst(x, z, 力度)` | — | [SPLASH.md](./SPLASH.md) 第 5 节 |
| 抄网 | `place(x, y, z, 柄的方向, 网兜拉多长, 晃多少)`、`hide()`；路径是玩法这边的 `scoop.js` | — | [NET.md](./NET.md) 第 5 节 |
| 手机瞄准 | 玩法报出 `fishing.watch`（要镜头看着的点） | 瞄准的俯仰 | [PHONE-LOOK.md](./PHONE-LOOK.md) 第 5 节 |
| 震动 | `haptics.impact`、`notification`、`playTransient`。哪一下在哪震见 [PLAY.md](./PLAY.md) 第 11 节 | — | [HAPTICS.md](./HAPTICS.md) |

- **物料之间也只走口子。** 线要拉竿，走 `rod.setTipTether`；线要知道导环在哪，走 `rod.linePath`。手机的瞄准要动竿，走 `rod.setAim`。这三个是给物料用的，玩法不要直接调。想让竿受力，改线的远端或线长；出了水的重量走 `rod.setTipLoad`。
- **物料报数，玩法判断。** 物料给出的是量出来的东西：余线多少米，张力多少牛，鱼在哪。这个数意味着什么（该出线了、线断了、算咬口了）不写在物料里。
- **读数要在源头量。** 想知道手甩得多快，量手机的角度，不量竿尖：竿身软，竿尖先落后再弹过去，它的速度说的是竿身。隔着一个有弹性、有惯性的东西去读输入，读到的是那个东西。见 [PLAY.md](./PLAY.md) 第 4 节。
- **替身要标出来。** 规则还没做全、先用一个简单的顶上时（现在是每条鱼都咬死），在代码里标 `Stand-in`，在 [PLAY.md](./PLAY.md) 第 13 节列出它和需求差在哪。别的代码不要依赖替身的行为。
- **随机数从外面给。** 玩法里要取随机的地方收一个 `random`，不直接调 `Math.random`。这样同一个种子能把一整竿原样重跑，才比得出前后差在哪。
- **每个物料要能单独检查**，不必走完一竿才看得到。

| 物料 | 怎么单看 |
|---|---|
| 一条鱼 | `fish.html`，有游速、发力、弯身滑杆 |
| 鱼群的游动 | Node 里跑 `flock.js` |
| 鱼竿 | 设置面板"鱼竿"一栏；Node 里跑 `rodFlex.js` |
| 鱼线 | Node 里跑 `lineCurve.js`；页面里甩一竿，饵落水后带竿 |
| 饵 | Node 里跑 `lureMove.js` 的固定、挂、飞、拖 |
| 水花 | Node 里跑 `splashBurst.js`；页面里甩一竿对着落点截图 |
| 抄网 | Node 里跑 `scoop.js`：落网的速度、圈沉多少、网兜拉多长；页面里钓一条对着网截图 |
| 一竿的流程 | Node 里用假的竿和线跑 `fishing.js`，不给鱼群就是没有鱼的一竿；桌面用空格键代替手指 |
| 鱼游向饵、挂在线上 | Node 里用真的 `flock.js` 跑 `visit.js` 和 `fight.js` 的 `brain`；整竿再接上 `rodFlex.js` 和 `fishing.js` |
| 出了水的鱼 | Node 里对一条假鱼调 `hung.js` 的 `poseHung`，每帧由三个角还原鼻尖和背，量一帧转多少 |
| 咔咔、鱼压竿多重、鱼甩多用力 | Node 里各跑 `reelClick.js`、`tipWeight.js`、`kick.js` |
| 手机瞄准 | Node 里给 `phoneLook.js` 喂合成的 `deviceorientation` 事件，读 `look()`；给 `aim.js` 喂转动和按住，读镜头和竿各得多少 |

## 2. 坐标和单位

单位是米、秒、弧度、千克、牛顿。设置面板上给人看的角度用度，重量用克。

| 对象 | 约定 |
|---|---|
| 世界 | +Y 向上。陆地在 +Z，海在 −Z。水面在 y = 0 附近 |
| 镜头 | 默认 `(0, 1.7, 2)`，朝向 100°，俯仰 −10° |
| 朝向角 yaw | 绕 +Y。yaw = 0 朝 +Z，增大时转向 +X。前进方向是 `(sin yaw, cos yaw)`。镜头的 yaw 增大是向左转，所以它的左边是 `(cos yaw, −sin yaw)` |
| 鱼 | 头在 holder 的局部 +Z。旋转顺序 YXZ。正的 X 是低头。正的 yaw 是向鱼自己的左转。嘴在中心前面 0.485 个体长、中线下面 0.073 个体长 |
| 出了水的鱼 | 记鼻尖和背两个方向，三个角从它们读出来，见下面第 3 节 |
| 鱼竿 | 局部 +Y 从竿尾到竿尖。局部 +Z 是下面，导环和渔轮挂在这一侧。根节点是镜头的子节点 |
| 渔轮 | 原点在轮脚和轮座相接处。+Y 指竿尖，+Z 远离竿，+X 是钓手左手侧 |
| 鱼线 | 所有点都是世界坐标。对象加在场景根上，不挂在竿或镜头下面 |
| 抄网 | 原点是圈的中心。+Y 朝上，是网口。柄沿 +X。圈始终水平。对象加在场景根上 |
| 屏幕 | 设计空间 390×844。触控先过 `clientToDesign` |

新加的模型也按"头或尖端朝局部正轴"来摆，并在文件头写明哪根轴是什么。

**模型上要用到的点在模型上量。** 鱼嘴、钩、线头这种要和别的东西对上的点，把模型加载出来量顶点，不按"大概在中轴最前面"估。鲷鱼的吻端在中轴下面 3 厘米，估的那一版线连到了额头上。

## 3. 会动的东西

出处：[FISH-SCHOOL.md](./FISH-SCHOOL.md) 第 2 节，[ROD.md](./ROD.md) 第 2 节，[PHONE-LOOK.md](./PHONE-LOOK.md) 第 2 节，[LURE.md](./LURE.md) 第 2 节，[PLAY.md](./PLAY.md) 第 2 节。

### 对所有会动的东西

- **动作连续。** 目标可以突变，物体不能。位置、朝向、速度都朝目标逼近，不瞬移，不突然掉头。
- **帧率不改变结果。** 逼近用 `1 - exp(-k·dt)`，不用固定的每帧比例。目标自己在动时，按它在这一帧里匀速移动来精确积分（`rodHold.js` 的 `chase`）。有弹簧的东西用固定的细步长（`rodFlex.js` 是 1/480 秒）。`dt` 在入口处已经封顶到 1/20 秒。改完在 20、30、60 帧下各跑一遍，数应当一样。
- **只用位置去追，不对输入求加速度。** 镜头和手指给的输入是一帧一帧不均匀地来的，差分两次就全是尖峰。有惯性的东西写成"一个点被弹簧拉向它该在的地方"，输入只提供"该在的地方"。手机的瞄准从姿态直接读，不从加速度积分。见 [PHONE-LOOK.md](./PHONE-LOOK.md)。
- **不均匀的输入先平滑再用。** 拖动的镜头是一步一步转的。读它的东西先过平滑，并且相对平滑后的值来量，不相对原始值。否则每一步的不均匀都会直接跳到屏幕上。
- **不设撞上去的上限。** 上限写成越靠近越硬，或者缓缓靠近（比如 `tanh`）。硬夹会让动作在上限处冻住。
- **硬的连接放进同一个细步长里算。** 两样东西互相拉扯时（线拉竿），拉力要在细步长里按当时的位置重新算。每帧算一次再当成恒定的力交过去，硬一点就会越抖越大。
- **长度不变的东西按转角摆，不按位移推。** 竿的每一节转一个角度，长度就不会变。把点横着推出去，弯得越大就越长。
- **换状态只换目标，不换算法、不拷贝。** 镜头从"追手机"变成"不动"再变成"看着落点"，变的只是它在追什么；饵从飞变成拖，位置原样交过去。在切换的那一帧拷贝一份、改一下基准，下一帧就可能跳。
- **数量不在某一帧归零。** 落水后线上的余线、松手后的线速、看完落点后镜头和手机之间的夹角，都是很快地退掉，不是一帧清零。能写成时间的函数就写成时间的函数（收线的线长、水花的形状），不积分。
- **能给定点就不给动点。** 让镜头去看一个地方时，给它落点这样不动的点，它转过去一次就停。给它一个一直在动的东西，画面就跟着起伏。
- **硬的东西按位置去追，不按力差加速。** 鱼被线拉着时，让它游到"线的拉力正好等于它的力"的那个位置，不是按力差多少给它速度。线越短越硬，按力算的会冲过头再被拽回来，越硬抖得越厉害；按位置追，多硬收敛都一样。
- **隔着一帧互相读的两样东西，不要靠一点点余量互相顶。** 竿读的是饵上一帧的位置，饵读的是竿尖上一帧的位置。让一个重物靠拉长线两三厘米去压竿，两边就隔着一帧互相等，张力在 0 和尖峰之间跳，各帧率的结果也不一样。让一边单向跟随：重量直接给竿（`setTipLoad`），饵刚性地挂在竿尖下面。
- **能指向任何方向的东西，不用朝向角记方向。** 朝向、俯仰在正上方和正下方没有意义：鼻尖经过竖直时朝向会转半圈，东西就翻了面。记两个方向（朝哪、背朝哪），每帧各转一点，角度从它们读出来。
- **直接叠在姿态上的量不能一帧跳。** 幅度、力度这类乘在摆动上的数，突然变大时摆动的当前值也跟着跳。让它在零点几秒里加上来。
- **跟着量走的东西按量算，不按时间算。** 线出去多少就咔几下、让出多少线，都是长度的函数，不是"每秒几次"。这样不用管帧率，快慢也自然跟着走。
- **看不见的时候才能一步挪。** 被网带出画面的鱼要回到鱼群，只在它已经看不见时、挪到画面外，再让它自己游回来。
- **贴在别的东西上的，取那个东西这一帧的位置。** 饵收在竿尖时跟的是这一帧画出来的竿尖，不是上一帧算好的那个点。慢一帧在快速甩动时就是十几厘米的脱节，线还会把留在原地的那一头当成锚点去拉竿。

### 对鱼

- **先定目标，再游过去。** 行为只写"想去的朝向、速度、深度"，真正挪位置的只有一处（`swim.js` 的 `swimFish`）。
- **鱼不横移。** 水平面上只沿鼻尖方向前进。任何新的力都先变成目标朝向和速度，包括被线拉住或挡住。
- **鱼不能倒着游，也不能原地掉头。** 要去的地方在身后时，它得绕过去。游过了头就继续往前，离开一段再掉头，否则它会把目标压在肚子下面一直打转。要掉头时先慢下来。
- **出了水的鱼不游。** 它是线上或网里的一个重物，从嘴上挂着，位置由 `hang` 直接给。这是唯一的例外，见 [FISH-SCHOOL.md](./FISH-SCHOOL.md) 第 7 节。
- **加速快、减速慢。**
- **随机要有各自的钟。** 每条鱼的节奏、幅度、间隔出场时各取一次，不共用一个计时器，也不用固定循环。

### 让人感觉得到

出处：[PLAY.md](./PLAY.md) 第 2 节。

- **先有看得见、摸得着的回报，再说流程完整。** 一段玩法走得通但画面上和手上都没有东西，不算做完。规则可以先收窄，回报不能省：鱼带着线走、竿被压弯、鱼咬着饵被提起来，这些要在第一版里。
- **状态先长在东西身上。** 鱼在冲还是在歇、有力还是没力，先是鱼自己游得不一样、竿弯得不一样，震动和声音是在这上面再加一层。只靠震动区分的状态，关掉震动就没有了。
- **事情发生的那一刻要有东西。** 出水、落网、起冲这种时刻，同时给画面（水花、猛甩一下、网一沉）和手（震一下）。持续的状态靠节奏：出线越快咔得越密。
- **活的东西不能只是越来越弱。** 一直衰减的摆动，到后面看着是死的。隔一阵重新激一下，间隔每次重取。

## 4. 代码怎么放

| 目录 | 内容 | 语言 |
|---|---|---|
| `src/main.ts`、`src/adapt/`、`src/utils/` | 壳：启动、适配、安全区、震动 | TypeScript，strict |
| `src/shore/` | 岸边场景和它的接线，鱼竿、渔轮、鱼线、饵、水花、抄网、手机瞄准，手指和设置面板 | JavaScript |
| `src/shore/minamo/` | 水面，第三方 MIT 代码 | JavaScript。尽量不改 |
| `src/fish/` | 鱼的模型和游动，出了水的鱼怎么挂 | JavaScript |
| `src/play/` | 玩法：这一竿的规则。工程里唯一写钓鱼规则的地方 | JavaScript |

`npm run build` 里的 `tsc` 只严格检查 TypeScript。`.js` 文件不做类型检查，写错属性名不会报错，所以 JS 的改动要跑起来看。

### 分层

- **一个文件一件事。** 文件头用两句话写清：`Owns` 它管什么，`Does not own` 它不管什么、那件事在哪个文件。
- **按"回答什么问题"分层，数据只往一个方向走。** 上游不知道下游。现有的链：

| 物料 | 链 |
|---|---|
| 鱼群 | `shoal`（整群）→ `behaviors`（想做什么）→ `swim`（怎么游）；出了水的走 `hung`（从嘴上怎么挂、怎么甩）；`flock` 串一帧，`school` 接到场景 |
| 鱼竿 | 镜头 → `rodHold`（握）→ `rodFlex`（弯）→ `rod`（摆骨骼）；`rodBeam`（梁）在启动时解一次，供 `rodFlex` 查 |
| 鱼线 | `rod.linePath`（竿上的点）→ `lineCurve`（形状）→ `line`（画）；`line` 再把远端和线长交回 `rod` |
| 饵 | 玩法选动法 → `lureMove`（位置）→ 线的远端和 `lure`（模型） |
| 水花 | 调用的人给位置和力度 → `splash`（记时间、画）← `splashBurst`（这一刻的形状） |
| 抄网 | 玩法给鱼嘴的位置 → `scoop`（圈在哪、鱼落到哪、网兜什么样）→ `net`（画）和鱼群的 `hang` |
| 玩法 | 饵这一半：`swing`（甩多用力）、`retrieve`（收多快）、`lineOut`（线放出多长）→ `fishing`（这一竿走到哪）。鱼这一半：`visit`（鱼怎么游向饵）、`fight`（钩住的鱼用多大力、往哪游）、`haul`（顶着鱼收多快、出多少线）、`reelClick`（手里咔不咔）、`tipWeight`（鱼压竿多重）、`kick`（鱼甩多用力）、`scoop`（抄网走到哪）→ `catch`。`fishing` 驱动 `catch`，两个都 → 物料的口子 |
| 手机瞄准 | `phoneLook`（读姿态）→ `aim`（镜头追什么，剩下的给竿）→ 镜头，以及 `rodHold`（握）；`startShore` 的 `applyPhone` 串一帧 |

- **模拟和渲染分开。** 算数的那几层不引 Three，可以在 Node 里跑：`flock.js` 往下（含 `hung.js`）、`rodBeam.js`、`rodFlex.js`、`lineCurve.js`、`lureMove.js`、`splashBurst.js`、`phoneLook.js`、`aim.js`，以及 `src/play/` 下的全部。只用 Three 的数学、不碰场景的（`rodHold.js`）也算在算数这一边。
- **玩法也分"只算数的"和"接线的"。** `swing`、`retrieve`、`lineOut`、`visit`、`fight`、`haul`、`reelClick`、`tipWeight`、`kick`、`scoop` 各回答一个问题，互相不知道对方，也不认识物料。认识物料的只有两个：`fishing.js` 管饵这一半和整竿走到哪一段，`catch.js` 管鱼这一半。新的规则先想它回答的是哪个问题，写成新的只算数的文件，再到这两个里接：没有鱼时的事进前者，鱼的事进后者。接线的文件长了，先看是不是里面混着一段该单独回答的问题。
- **只在启动时算一次的东西单独放。** 梁的振动和深弯表在 `rodBeam.js`，每帧的运动在 `rodFlex.js`。热路径只查表。
- **`startShore.js` 只负责创建、接线和每帧调用。** 不要把游动、建模、弯曲、玩法写进去。输入和界面也不写在里面：手指在 `finger.js`，设置面板在 `tunePanel.js`，它只决定读到的东西交给谁。玩法它只做三件事：创建 `fishing`（把鱼群和震动也交给它），每帧把手指、有没有传感器、镜头朝向和瞄准的俯仰交给它，把它报出的 `watch` 换成方向交给 `aim`。每帧的顺序写在 [ENTRYPOINTS.md](./ENTRYPOINTS.md) 第 2 节，后面的依赖前面的。

### 写法

- **尺寸和调节量放在文件顶部的常量里**，带一句说明：单位，以及调大调小会怎样。
- **形状用数据表。** 渔轮的 `[半径, y]` 轮廓、鱼的 `SPINE` 表、竿的 `STIFFNESS` 和 `DENSITY` 表。改形状、改调性就是改表。
- **能推出来的数不另外填。** 竿身的质量由频率和刚度定出来，梁的段数跟着骨骼数走。两处各填一个数，迟早对不上。
- **代码建模的东西按能动的部件分组**，每个组的原点放在它自己的转轴上。
- **热路径不分配。** 每帧要用的向量、四元数、数组在创建时建好，循环里只改写。
- 注释用英文，写"为什么"和约定，不复述代码。文档用中文。

### 画的顺序和大小

- **半透明的东西不放进主场景。** 主场景先画，水面后画，盖在已有的东西上。半透明的东西在主场景里会先和海底混在一起，再在水面上留下一个洞。落在水面上的半透明物放进 `startShore.js` 的 `onWater` 场景，它在水面之后画。测深度，不写深度。见 [SPLASH.md](./SPLASH.md) 第 2 节。
- **不透明的可以放主场景。** 抄网的网兜是不透明的细线，在主场景里，看得见里面的鱼。只有半透明的才要挪到 `onWater`。
- **不为了局部的效果改海面。** 水花、涟漪、泡沫都是放在海面上方的东西，不动 `src/shore/minamo/`。
- **大小按真实的东西定，远处放大要有上限。** 10 克的饵落水是一个小"噗通"。为了远处看得见可以按距离放大一点，放多了看起来就是另一样东西落了水。
- **颜色是场景线性的。** 渲染器不做色调映射，曝光在后期里而且远小于 1，要出来是白的得比 1 亮一些。

## 6. 默认值和设置面板

出处：[ENGINEERING.md](./ENGINEERING.md) 第 6 节，[AGENTS.md](../AGENTS.md) 硬性约定第 9 条。

- **默认值在代码里，表在文档里，面板只是试看。** 面板上试出来的数不写回默认值，除非明确要求改默认。
- 水面外观已定。启动默认值写在 `startShore.js`，对应的表在 ENGINEERING 第 6 节，两处要一致。
- 竿和线的调节量在各自文件顶部，对应的表在 [ROD.md](./ROD.md) 第 3 到 5 节和 [LINE.md](./LINE.md) 第 4 节。手机瞄准的在 `phoneLook.js` 和 `aim.js` 顶部，表在 [PHONE-LOOK.md](./PHONE-LOOK.md) 第 3、4 节。饵的在 `lureMove.js` 和 `lure.js` 顶部，表在 [LURE.md](./LURE.md)。玩法的在 `src/play/` 各文件顶部，表在 [PLAY.md](./PLAY.md)。改了常量，同一次改动里把表改掉。
- **面板里有两种滑条，不要混。** 一种调的是物料自己的默认外观（雾、水、镜头、鱼竿的安装姿态）。另一种是替还没做的玩法临时送数（现在只剩竿尖负重）。后一种在代码里标明 `Trial only`，玩法接上以后拿掉，不要让别的代码依赖它。
- **调手感用的读数放在设置面板里。** 面板的"这一竿"一行显示玩法正在读到的数。它是给调常量的人看的，不是给玩家的提示：需求不许用文字告诉玩家该做什么。
- **需求里没定的数先填一个起点，并写明是起点。** 填在代码顶部的常量里，表在设计文档里，另外在 [PLAY.md](./PLAY.md) 第 13 节列出来哪些是先填的。真机上试出来以后改常量和表。
- **读数跟着玩法加。** 玩法多了一个要调的量（张力、出线速度、气力、冲还是歇），就在"这一竿"里加上它，调的人才对得上画面和数。
- **桌面的替身只为把流程走通。** 桌面没有传感器，也不能甩手机：空格键代替手指，按住的时间代替力度。代码里标明 `stand-in`，不为它改规则，手感以真机为准。

## 7. 改完怎么验

按改的东西选，至少做一项，并在交付时说清做了哪项、没做哪项。

| 改了什么 | 怎么验 |
|---|---|
| 任何东西 | `npm run build` 通过；游戏页面加载后控制台无报错。JS 不做类型检查，构建通过不说明能跑 |
| 接线、输入、界面、画面 | 在页面里走一遍：拖动转镜头，空格甩一竿再收回来，打开设置面板。可以用无头 Chrome 经 DevTools 协议发按键、读 DOM、截图，WebGPU 要加 `--enable-unsafe-webgpu` |
| 模型外形 | 从几个角度截图看；再看第一人称镜头里的样子 |
| 只整理结构、不该改变结果 | 证明前后一致，见下。挪了输入或界面的代码，Node 里验不到，要在页面里把拖动、按键、面板各用一遍 |
| 鱼的游动 | 在 Node 里跑 `flock.js` 几分钟，量：运动方向和鱼头的夹角（应为 0）、鱼群散布、两条鱼贴得太近的比例。和改之前的数对比 |
| 鱼的身体姿态 | `fish.html` 把发力、弯身拉到最大，看有没有撕裂、方向对不对 |
| 竿的弯曲 | 在 Node 里跑 `rodFlex.js`：甩一下再急停，量各阶频率、每次回摆的幅度、竿长、各段开始落后的先后；匀速转动时的偏移应接近 0。和改之前的数对比 |
| 竿跟镜头 | 在 Node 里转一个假镜头：量匀速转动时落后的角度、手的位置有没有漂；再用不均匀的步子转，量竿尖在镜头里每帧运动的变化 |
| 鱼线的形状 | 在 Node 里跑 `lineCurve.js`：画出的长度等于线长，两端对上，余线正负对 |
| 线拉竿 | 远端固定，把线收短、把竿抬起和带向旁边，看张力稳定在多少；在 20、30、60 帧下张力应当收敛到同一个数。把线收短到 2 米、把竿带偏到 70°，打印每个关节的弯角：应当同号，从竿尾到竿尖平缓变化，不能有反向和单个关节的折角。再在页面里把余线拉到两头各看一眼 |
| 手机瞄准的角度 | 在 Node 里给 `phoneLook.js` 喂由已知姿态算出的 `alpha` / `beta` / `gamma`：只转一个方向时另两个角应为 0，包括手机正好竖直的时候；转一整圈、大幅乱晃后回到原姿态，三个角应回到原值；`chaseAngle` 在 20、30、60、120 帧下结果一样 |
| 镜头和竿怎么分 | 在 Node 里给 `aim.js` 喂一段转动：每一帧镜头加竿应当正好等于瞄准；按住时镜头的数不变，松开后镜头回到瞄准、竿回到 0；`reset` 之后镜头在给定的方向上。给它一个要看的方向：镜头转过去，开始和结束都没有一帧的突跳，各帧率下最快的转速一样，俯仰不出上下限；方向不动时俯仰只朝一个方向变，不来回；看完交还时让瞄准离镜头几十度，量镜头最快转多快，不能是一下甩过去 |
| 饵的运动 | 在 Node 里跑 `lureMove.js`，20 到 120 帧各一遍：不拉它时按时间量下沉的深度，各帧率一致，到底是缓缓停住；飞行的落点等于要的距离，按停以后落得更近；拖的时候饵的位置和线长各帧率一致，停手后拉长量回到 0；挂的时候离竿尖不超过线长，最后停在正下方 |
| 收线的速度 | 在 Node 里跑 `retrieve.js`：各帧率下收的线长一个数都不差；松手再按，线速不跳 |
| 线放出多长 | 在 Node 里跑 `lineOut.js`，或经 `fishing.js` 量落水前后的余线：各帧率下余线是渐渐退掉的，每帧的变化折合成速度没有尖峰 |
| 一竿的流程 | 在 Node 里用假的竿和线跑 `fishing.js`，不给鱼群：前三段按顺序走完，落水那一下按着不收线，落水前后线上的余线是渐渐收掉的、没有一帧的突变，飞行中按下落得更近，收完回到空杆并解开镜头；每一帧饵的位移不能有突跳 |
| 鱼游向饵 | 在 Node 里用真的 `flock.js`，几十个随机种子、20 到 120 帧，饵停着和在收各一遍：每一条都要碰到钩，量最慢的一条用了多久。鱼不能倒着游，最容易出的毛病是绕着饵打转 |
| 钩住的鱼、顶着鱼收线 | 在 Node 里用真的 `flock.js`、真的 `rodFlex.js` 和 `fishing.js` 跑几十竿，一直按、只在歇的时候按、完全不按各一遍：鱼的运动方向和鱼头的夹角是 0；张力停在出线点上，尤其是线只剩四五米的时候；鱼不绕到身后；一直按着一定收得到身边，完全不按线也不会越放越多；20 帧和 60 帧下用的时间相近 |
| 提鱼出水 | 同一套东西接着跑到抄网出画面为止：20 帧和 60 帧下鱼被提到的高度、竿被压低多少应当一样；量竿尖每帧走多快，到身边、鱼脱钩、落网和网出画面的那几下不能有一帧的弹跳。再在页面里对着挂起来的鱼截图。每帧由三个角还原出鱼的鼻尖和背两个方向，量它们一帧转多少度：挂着和在网里时不能有一帧的翻面，甩的力度突然加大的那一帧也不能 |
| 鱼的物料加了新的目标 | 同一个随机种子，改之前和改之后各跑一遍 `flock.js`，中间取走一条再放回，每条鱼的位置、朝向、速度一个数都不差 |
| 水花 | 在 Node 里跑 `splashBurst.js`：水珠的高度不为负，结束时每颗的大小和每一圈的宽度都是 0，量一下最高和最宽各是多少。再在页面里对着落点连截几帧 |
| 手感、震动、甩竿、手机瞄准的方向 | 只能真机。桌面没有马达，也没有姿态传感器；桌面用拖动看画面 |

**多跑几个种子。** 带随机的东西（鱼游向饵、遛鱼）只跑一次看不出毛病：鱼绕着饵打转是六十个种子里出五个。至少几十个种子，每个帧率各一遍，数一共有几次没走完。

**页面里跑不稳要说出来。** 用无头 Chrome 走一竿时，页面偶尔会在中途自己重载，没有报错，重跑又是好的；几次都发生在刚杀掉上一轮的开发服务器就重启之后，原因没有查实。遇到了重跑，并在交付时写明跑了几次、几次没走完，不要只报成功的那次。

**整理之前先留一份。** 要证明前后一致，得有"前"。动手整理结构之前，把当时的 `src` 提交掉或者拷一份，录数的脚本对着两份各跑一遍。

**证明前后一致的办法。** 画面可以逐像素比。会动的东西用录数的办法：写一段固定的输入（镜头怎么转、哪一帧改什么），每帧把要比的数全录下来，改之前存一份，改之后再跑一遍，逐个数比。鱼用同一个随机种子比位置和朝向。竿和线比每节骨骼的世界矩阵、线上每个点、张力和余线。玩法用假的竿、线、饵、抄网，加上真的鱼群和竿身，把它对物料的每一次调用和参数、每条鱼每帧的位置和姿态录下来比；几种按法各跑几竿，要覆盖到五段和每一个口子。只是挪代码、不改算式的整理，差值应当正好是 0，不是"很小"。输入里要有不同的帧长、一帧的突跳和每个口子的调用，不然比不出问题。

动起来好不好看，截图和数值都判断不了，要人看。交付时把这一点说明白，不要说成已经确认。

同一件事在两个帧率下的结果差得多，是算法有问题，不是精度问题。提鱼时竿被压弯多少，60 帧和 20 帧差了一倍，查下去是竿和饵隔着一帧互相等。

估出来的数要拿真的东西复算一遍。抛投的力度第一版量竿尖，门槛是按"竿是一根硬棍"估的，结果怎么甩都出不了线；把真实的竿模型在 Node 里甩一下就能看出竿尖只有估的五分之一。

### 物料的设计文档

FISH-SCHOOL、ROD、LINE、LURE、SPLASH、NET、PHONE-LOOK 是同一个写法，新加的物料照着来：

1. **状态**：一两句。实现到哪了，是不是物料，规则在哪份文档。
2. **分层**：每个文件回答什么问题，数据往哪个方向走。
3. **不能破的规则**：两三条，改这个物料时不管改什么都要守的。
4. **每一层**：它怎么做，以及一张常量表：值、管什么、调了会怎样。
5. **给玩法留的口子**：接口表，并写明哪些不许从外面碰。
6. **还没做**。
7. **改的时候**：想改某件事该动哪个文件，改完怎么验。

玩法的文档 PLAY.md 也是这个写法，"每一层"是每个只算数的文件各一节，另外多几节：一竿分哪几段，和物料的接线，量出来的数，以及需求里没定、这里先填的数和出入。

新加一个物料时还要：在 AGENTS 的入口地图和 ENTRYPOINTS 第 5 节各加一行，在本文第 1 节的口子表和单看表各加一行，在 ENGINEERING 第 2 节的目录和第 10 节的变更里记一笔。

## 9. 提交

- 一次提交做一件事。提交信息是一句英文祈使句，首字母大写，句号结尾，说做了什么。例：`Split the school into layers and the reel into its own part.`
- 改行为的提交和只整理结构的提交分开。后者才能用"前后一个数都不差"来验。所以整理之前，先把改行为的那部分提交掉。
- `dist/` 和 `ios/App/App/public` 是产物，不手改。
- 改 Swift 改 `plugins/native-haptics/`，再跑 `ios:bootstrap`。不要直接改 `ios/` 里的拷贝。
